# Knowledge Graph Schema

## Storage Architecture

The knowledge graph is scoped per product. All files live under `{vault}/{product}/Knowledge Graph/`.

- `{vault}/{product}/Knowledge Graph/graph.json` - machine-readable source of truth; Claude reads this when doing tasks
- `{vault}/{product}/Knowledge Graph/nodes/[type]/[id].md` - human-readable node files editable in Obsidian
- `{vault}/{product}/Knowledge Graph/graph-view.md` - DOT code block regenerated by Python, rendered by obsidian-graphviz
- `{vault}/{product}/Knowledge Graph/pending/` - extracted insights awaiting the user's review
- `{vault}/{product}/Knowledge Graph/approved/` - processed review files (audit trail)
- `{vault}/{product}/Knowledge Graph/_index.md` - human-readable index of all nodes
- `{vault}/{product}/Knowledge Graph/_log.md` - append-only ingestion log

## Node Types

| Type | Description | Examples |
|------|-------------|---------|
| `Product` | A product the user manages | Acme |
| `Stakeholder` | A person with a role and relationships | Jane, Priya, Marcus |
| `Team` | A group or external team | Support Team, Mobile BU, Legal |
| `Feature` | A committed feature or requirement | offline sync, multi-language onboarding |
| `Decision` | A made and recorded decision | EU launch deferred to R2 |
| `Commitment` | A hard owner + deliverable + date | Marcus: pricing API live by Apr 30 |
| `Constraint` | A legal, technical, or business limitation | EU data residency blocks launch until R2 |
| `Metric` | A tracked KPI or success measure | Unique users, conversion rate |
| `Milestone` | A key date or delivery gate | Beta release May 18, pilot end of April |

## Edge Types

| Type | Meaning | Example |
|------|---------|---------|
| `owns` | Person or team owns a product, feature, or metric | Jane owns offline sync |
| `responsible_for` | Person is accountable for a deliverable | Marcus responsible_for pricing API |
| `committed_to` | Hard commitment: owner + deliverable | Marcus committed_to pricing API Apr 30 |
| `depends_on` | Item cannot proceed without another | Beta release depends_on mobile testing |
| `blocks` | Item is preventing another from progressing | Mobile testing blocks beta release |
| `decided_by` | Decision was made by a stakeholder | EU deferral decided_by Legal |
| `constrains` | Constraint limits a product or feature | Data residency requirement constrains EU launch |
| `reports_to` | Org relationship between stakeholders | |
| `relates_to` | General semantic relationship | Onboarding relates_to adoption metrics |
| `supersedes` | Newer fact replaces an older one | Updated metric supersedes prior reading |

```json
  ],
  "edges": [

      "to": "feature-offline-sync",

    }
  ]
}
```

## Fact Quality Rules (enforced during review)

A candidate may enter the graph only if it meets one of these criteria:

1. **Named entity** - a person, team, or product that exists and has a confirmed role
2. **Hard commitment** - has an explicit owner, a stated deliverable, and a date or trigger
3. **Confirmed decision** - was decided (not proposed or discussed) and has a clear outcome
4. **Active constraint** - is a real limitation currently in effect (legal, technical, or business)
5. **Tracked metric** - has a name, a value, and a known date of measurement

The following are explicitly excluded from the graph:
- Ideas, brainstorms, or proposals without a decision
- Open questions
- Opinions or preferences without a decision attached
- Speculative future plans without a commitment

These belong in meeting notes or session documents, not the knowledge graph.
